# Task 010 — Решения по автосохранению и макету страницы

## Статус и владелец

- Статус: `Done` (решения владельца получены; Auto Save отложен)
- Владелец: владелец продукта
- Приоритет: P1 (блокирует окончательную спецификацию Tasks 006 и 008)

## Контекст

UI sketch включает Auto Save и страницу настроек Page Size, Orientation, Margins, но не определяет модель хранения страницы и что именно означает Auto Save. Архитектура не должна предполагать скрытую запись поверх исходника.

## Цель

Утвердить продуктовые правила, которые нельзя безопасно выбрать без владельца.

## Область работ

Записать решения в ARCHITECTURE.md, AGENTS.md и затронутых task-карточках:

1. Auto Save: сохранять непосредственно в исходный файл или в отдельную recovery copy; интервал; поведение для untitled document; восстановление при запуске; сообщение об ошибке; взаимодействие с dirty state/обычным Save.
2. Page Setup: только глобальные defaults или индивидуальные параметры каждого документа; если индивидуальные — где хранить их, учитывая, что обычный Markdown не имеет стандартного формата для таких метаданных.
3. Базовый размер страницы и допустимые правила для блока, превышающего полезную высоту страницы.

## Ограничения и предположения

- Не внедрять Auto Save и не записывать document metadata до фиксации решений.
- Не добавлять непереносимые proprietary Markdown front matter без согласования.
- Учитывать защиту пользовательских данных и явное поведение при ошибке.

## Критерии приёмки

1. Каждый пункт имеет явное выбранное поведение или пометку «отложено», с причиной.
2. Обновлены архитектура и task-карточки 006, 008, 009 либо создана отдельная задача реализации Auto Save.
3. Предположения не представлены как подтверждённые требования.

## План проверок

- Проверка согласованности решений между README, sketch, AGENTS.md, ARCHITECTURE.md и задачами.
- Кодовые тесты не требуются; реализацию не выполнять в рамках этой задачи.

## Зависимости и открытые вопросы

- Зависимости: нет.
- Открытые вопросы: все перечисленные решения требуют ответа владельца продукта.

## Исполнительский промпт

Не реализуй код. Подготовь владельцу продукта краткие однозначные варианты для Auto Save, хранения Page Setup, default page size и overflow page behavior. Учитывай, что запись поверх исходника может терять данные, а стандартный Markdown не задаёт универсального места для page metadata. После получения выбора внеси решения в ARCHITECTURE.md и связанные task-файлы; оставь `Draft` там, где вопросы не отвечены. Не придумывай ответы за владельца. В отчёте укажи принятое, отложенное и изменённые документы.

## Итог выполнения

### Принятые решения владельца (2026-11-10)

1. **Auto Save — отложен.** Явный Save остаётся; скрытая запись в исходник и
   recovery-copy механизм не реализуются в этом этапе. Причина: риск потери
   данных и отсутствие утверждённого recovery UX. Задача реализации Auto Save
   может быть создана отдельно.
2. **Page Setup — глобальные настройки приложения.** Размер/ориентация/поля
   хранятся в конфигурационном файле Settings Service (Task 009), не в Markdown
   и не в per-document metadata. Markdown остаётся переносимым.
3. **Default page:** A4 portrait, поля 20 мм со всех сторон. Значения
   конфигурируемы; ориентация и допустимые размеры/поля валидируются.
4. **Блок выше полезной области страницы:** переносится на новую страницу,
   может выходить за нижнюю границу с видимым предупреждением. Внутреннее
   разбиение блоков (таблиц/кода/абзацев) в первом paginated-срезе не
   выполняется; это явное ограничение, а не визуальная печать.
5. **Language:** English — default; дополнительные языки подключаются файлами
   `lang/*.ini` в корне приложения/конфигурации с fallback English.
6. **Config root:** пользовательский каталог Markpad (`AppConfigLocation` /
   `%APPDATA%/Markpad`, `~/.config/Markpad`), не каталог установки.
