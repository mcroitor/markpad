# Task 050 — Spike замены постраничной поверхности

## Статус и владелец

- Статус: `Done`; владелец: архитектор/координатор, исполнитель: C++/Qt.
- Решение владельца (2026-11-12): один QTextDocument + собственный page canvas;
  oversized-блок остаётся целым с предупреждением, без молчаливого обрезания.

## Контекст

Task 044 использует один QTextEdit, top margins и рисование поверх текста;
overflow и согласованность фактической геометрии требуют проверки. PDF использует
отдельный путь Qt layout (047). Рассматривается замена, включая per-page editors.

## Цель

Проверить реализуемость межстраничного редактирования до выбора архитектуры.

## Область работ

Включено: изолированный Qt-прототип, сравнение per-page поверхностей и одного
документа с собственной отрисовкой, результаты и рекомендации. Не включено:
замена production UI, изменение формата Markdown или PDF export.

## Ограничения и предположения

Qt/C++20, Windows/Linux, единая DocumentSession; внешние ресурсы не загружать.
Несколько листов — гипотеза, не утверждённое решение. Не обещать поддержку IME,
выделения или source mapping без реальной проверки.

## Критерии приёмки

1. В прототипе показаны два листа, ввод на втором, перенос блока при изменении
   размера, восстановление курсора и общая отмена правки.
2. Проверены навигация и выделение через границу листов, IME и совместимость
   с существующим versioned source mapping; пробелы воспроизведены и описаны.
3. Есть сравнение вариантов, ограничения Qt, риски производительности и решение,
   какие вопросы требуют выбора владельца; неудачный эксперимент допустим как
   результат, если blocker и альтернативы доказательно описаны.

## План проверок

Запустить прототип и целевые тесты на доступных Windows/Linux; зафиксировать
команды, фактические результаты, ручные IME/навигационные сценарии и отсутствие
проверок на недоступной платформе. Проверить безопасность активного содержимого.

## Зависимости и открытые вопросы

005, 044, 046. Нужны результаты эксперимента для архитектуры 051; выбор политики
oversized-блока и PDF принадлежит владельцу.

## Исполнительский промпт

Изучи эту карточку, `src/page_text_edit.*`, `src/continuous_editor.*`,
`src/page_layout.*` и mapping/историю. Создай изолированный Qt spike в рамках
указанного scope; не переключай production UI. Для каждого критерия приведи
сценарий и observed result, включая отрицательные результаты и платформы.
Верни файлы, команды, результаты, сравнение архитектур, ограничения и вопросы.
При невозможности проверить критический сценарий остановись с blocker, не
подменяй эксперимент предположением; обнови итог карточки.

## Итог выполнения

### Промежуточный результат

Создан опциональный `experiments/pages`: два независимых QTextEdit для двух
простых однострочных абзацев, одна настоящая DocumentSession и MD4C ReplaceText.
Тесты проверяют правку второго абзаца, локальную историю прототипа, отказ по
устаревшему token, перемещение виджета между контейнерами по измеренной высоте
его QTextDocument с сохранением позиции курсора и последующим undo, а также
синтетические Qt IME preedit/commit, включая перемещение во время композиции.
При изменении ширины и переносе строк проверено перемещение второго блока между
контейнерами без изменения source/token и потери позиции курсора. Отдельный
offscreen-тест показывает два контейнера фиксированного размера и проверяет
геометрическое включение двух текстовых виджетов; это не визуальная приёмка.
Встроенные отдельные QTextEdit не расширяют выделение через
границу по Shift+Right: нужна собственная межстраничная модель выделения.
Экспериментальный event filter переносит фокус по Left/Right без модификаторов
между двумя блоками; после перехода текст вводится в общую сессию. Отдельный
тест вручную устанавливает выделение в обоих виджетах. Это не реализация
единого выделения: Shift-навигация, мышь, copy/delete и направления выделения
между блоками не поддержаны и не проверены.

Это эксперимент с виджетом на абзац, **не** per-page rich-text editor и не
физическая пагинация: высота content area задаётся тестом, производственная
геометрия и листы на экране не проверялись; исходник — два простых абзаца.
Undo прототипа не является историей MainWindow. Отдельный тест проверяет mapping
и versioned command реального ContinuousEditor для простого абзаца, но не его
интеграцию с несколькими документами. Другой тест показывает отрисовку фрагмента
одного QTextDocument на изображении листа, обратное преобразование координат и
единое выделение через страницу. Это примитивы Qt, не интерактивный canvas.
Добавлены тесты штатной пагинации Qt: один абзац выше страницы и таблица из
30 строк занимают несколько страниц, что не соответствует принятому в Task 010
правилу целого блока. Для
общего page plan требуется собственное размещение, а не простое использование
`QTextDocument::setPageSize`. На существующем ContinuousEditor проверен fixture
с таблицей и fenced code: текст ячейки находится в QTextTable, код видим, HTML
script заменён placeholder, source не меняется. Это не проверка безопасности
новой поверхности или всех видов недоверенного GFM.

Отдельный Qt-тест переносит QTextEdit с QTextTable и двумя строками обычного
текста между контейнерами и проверяет сохранение таблицы, курсора и возможности
изменить ячейку. Он не использует отображение fenced code, MD4C mapping или
DocumentSession и не доказывает source-preserving перенос сложных блоков.
Два дополнительных теста переносят **весь** production ContinuousEditor между
контейнерами и выполняют versioned edit ячейки GFM-таблицы и тела fenced code;
ожидаемый Markdown и окружающие delimiters сохранены. Это не разбиение одного
документа между листами и не проверка общей истории приложения.
Дополнительный узкий эксперимент использует два текстовых page proxy: по известным
начальным позициям одного run в canonical ContinuousEditor тест переносит вставку
из первого proxy в ячейку таблицы, затем после повторного render — из второго в
fenced code. Обе versioned команды сохраняют остальные байты fixture. Это только
вставка в конец известного run с тестовыми offsets. В другом ограниченном fixture
вычисляется изменение по общим prefix/suffix: удаление символа ячейки передаётся
canonical editor; устаревший token и отклонённое удаление всего run откатывают
proxy без изменения сессии. После ручного обновления snapshot возможна правка
code. Это не общий production bridge: позиции run определены тестом, курсор при
откате не восстанавливается; rich-text-проекции, cross-run edits, составные
операции, обновление proxy после reflow и системная IME не проверены. Для
вычисления границ изменения выделен `proxyChange`; он не допускает разрыва
UTF-16 surrogate pair при замене emoji, что покрыто тестом. Существующий
`sourcePosition` также отклоняет позицию внутри surrogate pair, что проверено
на UTF-8 исходнике с emoji. Обратный `viewPosition` пока возвращает только
границу текста run; это совместимо с текущими ограничениями continuous editor.

Системная IME, реальный reflow во время композиции, интегрированная навигация,
перенос отдельных таблиц и code-блоков в многостраничной проекции и
производительность не проверены.
Архитектурное решение по этим данным принимать рано.

| Вариант | Подтверждено в spike | Остаётся реализовать/доказать |
|---|---|---|
| Отдельные текстовые поверхности | Простой versioned edit, курсор и Left/Right на границе двух виджетов | Полный координатор selection/navigation, системная IME, rich blocks, общая история приложения; тест использует виджет на абзац, а не на лист |
| Один QTextDocument и листы | Единый QTextCursor, hit-test и рисование фрагмента | Интерактивный canvas, ввод/IME/accessibility и собственная блочная пагинация; штатный Qt разбивает oversized-абзац |

Риск роста стоимости перерисовки и количества виджетов при больших документах
оценён качественно; производительные пределы не измерены.

### Прототип page canvas

Добавлен `experiments/pages/canvas_edit.*`: один QTextDocument, собственный
`QAbstractScrollArea`, блочная пагинация без spacer-блоков, отрисовка листов и
содержимого через `QAbstractTextDocumentLayout`, hit-test мыши и базовый ввод.
Тесты проверяют: несколько листов; клик и ввод на втором листе; undo через
документ; выделение мышью через три листа; IME commit на втором листе; наличие
отрисованного текста на листе; отсутствие пересечения блока с границей страницы.

Это подтверждает, что выбранное направление не требует нескольких QTextEdit и
сохраняет единый cursor/selection. Ограничения прототипа: только plain text без
таблиц и rich formatting; ContinuousEditor, MD4C mapping, source/token и общая
история MainWindow не подключены; нет copy/paste, accessibility, page numbers,
корректного preedit-overlay и инвалидации при смене шрифта (в тесте вызывается
ручной relayout); прокрутка и геометрия упрощены; системная OS IME не проверена,
только Qt input method events. Это доказательство примитивов, не production-view.

### Предварительная рекомендация

Для Task 051 рекомендуется **один канонический QTextDocument и собственный
page canvas**, а не несколько независимых редакторов:

- Единый курсор, выделение, IME и `ContinuousEditor` mapping сохраняются.
- Межстраничная навигация и выделение не требуют отдельного координатора и
  синхронизации нескольких QTextCursor.
- Штатную Qt-пагинацию нельзя использовать напрямую: она делит oversized-абзацы
  и таблицы, что нарушает принятое правило цельного блока. Нужен собственный
  план страниц из Task 052 и собственное размещение блоков.
- Основная новая работа — view: отрисовка листов, hit-test, ввод и прокрутка.
  Это меньше, чем собственный мост между независимыми редакторами с единой
  историей, mapping и selection.

Вариант отдельных поверхностей на лист пригоден для просмотра или будущего
развития, но для текущего редактируемого режима в spike требует собственной
межстраничной модели и не даёт преимуществ, оправдывающих её стоимость.

До утверждения 051 остаются решения владельца: допустимая политика oversized
блока в UI и PDF, требования к межстраничному выделению/copy, а также объём
поддержки системной IME и accessibility. Без отдельного прототипа canvas с
вводом нельзя обещать, что Qt-ввод и IME будут работать без дополнительной
работы; это главный риск выбранного направления.

Windows UCRT64: включение `-DMARKPAD_BUILD_PAGES_SPIKE=ON`, сборка target и
полный `ctest --test-dir build-task044 --output-on-failure`: 7/7. Ubuntu WSL,
GCC 15.2: Debug configure с той же опцией и локальным MD4C source, сборка
target и `ctest -R markpad_pages_spike --output-on-failure`: 1/1. Оба запуска
offscreen; Linux полный CTest, native visual QA и системная IME не выполнялись.
clang-format отсутствует в проверенных Windows PATH и Ubuntu WSL.

### Итог

Критерии 1 и 3 подтверждены прототипами и сравнением. Критерий 2 подтверждён для
Qt-событий ввода: межстраничное выделение мышью и IME commit/preedit проверены
синтетическими событиями; mapping совместим на узких fixtures. **Системная OS
IME, native visual QA и accessibility не проверялись** и остаются ручными/
последующими проверками, а не заявленным успехом. Владелец выбрал направление
для 051; production-код не изменялся.
