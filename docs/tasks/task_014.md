# Task 014 — MD4C списки, цитаты и вложенные операции

## Цель

Реализовать source-preserving операции со списками/цитатами в MD4C-прототипе.

## Область работ

Добавление/удаление пунктов, ordered/unordered/task lists, изменение вложенности,
многострочные пункты и контейнеры quote/list. Соседний исходник сохраняется.
UI и production-интеграция не включены.

## Ограничения и предположения

Использовать общий snapshot contract Task 013; подтвердить ownership диапазонов
контейнеров и безопасную границу пересериализации. Нельзя подменять полный диапазон
envelope известных дочерних bytes.

## Контракт v2

v2 заменяет v1: обязательные success/rejection fixtures разделены, добавлены
правила tightness/ownership/перенумерации и дочерние этапы. Definitions — единственный

Это спецификация следующей реализации, **не существующий C++ API**. Имена команд
ниже логические; при реализации использовать существующий `EditCommand` /
`applyEdit`, не добавлять параллельный редактор. Node id — индекс в текущем снимке,
не постоянный идентификатор.

### Общие входы, результат и ошибки

- Вход: parser-produced Document, SnapshotToken и одна типизированная команда.
  Token UUID/revision/SHA256 проверяется до операции, включая no-op.
- Все позиции — UTF-8 byte offsets либо индексы узлов/детей, не UTF-16.
  Позиция вставки между детьми: `0..count`; индекс удаления: `0..count-1`.
- Успех возвращает полностью разобранный Document с прежней identity и revision
  + 1. Только семантический no-op с сохранением исходных bytes оставляет revision.
  Одна составная операция indent/outdent повышает revision один раз.
- Ошибка возвращает отсутствующий Document и непустую диагностику, исходный снимок
  не меняется. Различать в сообщении snapshot mismatch, неверный target/index,
  неподдержанный source-map/context, invalid fragment, overflow и structural mismatch.
  Нельзя выдавать старый документ за успешную правку.
- После успеха вызывающий код заново получает узлы из результата; команды на старых
  индексах нельзя переносить между снимками без повторного разрешения цели.
- Пользователь подтвердил: после структурного изменения ordered list сохранять
  его start и записывать номера последовательно. Диапазон start и каждого
  полученного номера — `0..999999999` (GFM допускает до девяти цифр).
  Переполнение отклоняет всю команду.
- Перенумерация затрагивает только списки, у которых меняются состав/порядок LI
  (insert/remove/indent/outdent) либо kind/start. Task-state и quote wrap/unwrap
  не перенумеровывают окружающие списки. Неизменённые descendant lists также
  сохраняют исходные номера. No-op SetListKind не нормализует запись.

### Операции списков

| Команда / вход | Результат и ограничения |
|---|---|
| `InsertListItem(list, position, blocks)` | Вставляет один LI. `blocks` — UTF-8 Markdown fragment без NUL, содержащий хотя бы один отображаемый block. Пустой, whitespace-only и definition-only fragment — invalid fragment. Владелец выбрал поддержку definitions; scope/conflicts/reference bindings определяет Task 025 до реализации команды. Новый LI не task: начальное `[ ]`/`[x]`/`[X]` первого paragraph экранировать как буквальный текст без изменения отображаемого содержания. Обязательные multiline/nested формы заданы дочерними fixtures |
| `RemoveListItem(item)` | Удаляет LI вместе с его поддеревом. Пользователь подтвердил: последний LI удаляет весь список; соседние блоки остаются. Не превращать удаляемое содержимое в абзац |
| `SetListKind(list, unordered/ordered, start)` | Меняет вид всего списка, сохраняя порядок/поддеревья LI и task-state. Для ordered обязателен start, для unordered start не передаётся. Уже совпадающие kind/start — no-op без перенумерации исходного написания |
| `SetItemTask(item, none/unchecked/checked)` | Добавляет/удаляет task marker или задаёт состояние. Включение task разрешено, только если первый блок LI — непустой paragraph с обычным текстом, в том числе при tight list без P callback. Code/heading/quote в начале — явный unsupported. `none` удаляет checkbox, а не текст пункта. Уже совпадающее состояние — no-op |
| `IndentListItem(item)` | Один LI с его поддеревом переносится в конец дочернего списка предыдущего sibling LI. Первый LI не может быть indented. Используется последний дочерний list предыдущего LI, если его kind совпадает; иначе создаётся list исходного kind, ordered start = 1. Start существующих списков не меняется |
| `OutdentListItem(item)` | Только LI вложенного списка, чей parent list расположен внутри другого LI. Переносит выбранный LI сразу после enclosing LI во внешний list. Предшествующие/последующие siblings остаются в прежнем вложенном list; пустой list удаляется. Остальные дочерние блоки enclosing LI не перемещаются. Для top-level LI — явная ошибка |

Новая команда `SetItemTask` не отменяет существующую `SetTaskChecked`: последняя
сохраняет контракт mapped checkbox byte patch и не добавляет task к обычному LI.
Нормализация всего списка для checkbox toggle не требуется.

### Операции цитат

| Команда / вход | Результат и ограничения |
|---|---|
| `WrapInQuote(parent, first, count)` | Оборачивает непустой непрерывный диапазон block children одного parent в один QUOTE. Parent — document, quote или LI; не inline/span/table cell/list (у list дети LI, не произвольные blocks). Сохраняет порядок и содержимое; существующая quote получает дополнительный уровень |
| `UnwrapQuote(quote)` | Удаляет один уровень выбранной QUOTE, поднимая её block children в тот же parent на место quote. Допустимые parents те же; не удаляет содержимое и не снимает другие уровни |

Пустой selection, разные parents, выход за границы и неправильный node kind —
ошибка. Все wrap/unwrap операции structural, не no-op. Многострочные цитаты и
list/quote nesting входят в область реализации, а не исключаются из Ready scope.

### Source ownership и нормализация

- До мутации реализация обязана построить проверенный полный syntax range
  изменяемого контейнера, включая markers, continuation indentation, owned blank
  lines и окончания строк. EvidenceEnvelope Task 013 — только вспомогательное
  свидетельство, никогда готовый patch range.
- Граница замены — минимальный доказанный непрерывный контейнер: list для
  insert/remove/kind, LI или list при изменении task structure, общий предок
  затронутых lists для indent/outdent, выбранная последовательность blocks /
  quote для wrap/unwrap. Если последний list/quote исчезает, ownership всё равно
  вычисляется по исходному снимку.
- Если недостаточно диапазона без расширения на весь document, отказ
  unsupported; нельзя использовать root как способ обойти отсутствие source-map.
  Если сам выбранный контейнер занимает весь файл, его точная замена разрешена.
- Prefix/suffix вне patch range сохраняются побайтно, включая HTML/comments,
  definitions, пробелы и EOL. Разделитель между двумя соседними блоками не
  принадлежит автоматически первому: при неоднозначном ownership явный отказ.
- Правило разделителей: для поддержанного canonical source EOL последней
  непустой строки принадлежит блоку; следующие пустые separator lines не входят
  в его range, если отделяют от sibling вне контейнера. Пустые строки между LI
  одного списка принадлежат list, но не автоматически соседним LI.
  Для выбора последовательности blocks range включает separators между ними.
  Рanges отдельных LI могут не покрывать все bytes списка; это не ошибка.
- Контрольные byte fixtures (ASCII, offsets с нуля, escapes обозначают bytes):
  `source="pre\n\n- a\n- b\n\npost\n"` → list range `[5,13)`,
  replace `"- a\n"` → `"pre\n\n- a\n\npost\n"`;
  `source="pre\n\n- a"` → list `[5,8)`,
  replace `""` → `"pre\n\n"`;
  `source="pre\r\n\r\n> a\r\n> b\r\n\r\npost\r\n"` → quote `[7,17)`,
  unwrap replacement `"a\r\nb\r\n"` → `"pre\r\n\r\na\r\nb\r\n\r\npost\r\n"`.
  Тесты должны проверять сами ranges, prefix/suffix и полный ожидаемый source.
- Внутри изменяемого контейнера допустима нормализация structural markers:
  unordered `-`, ordered `<number>.`, task `[ ]` / `[x]`, quote `> ` (пустая
  quoted line `>`), continuation indentation по ширине выбранного list marker.
  Неизменённые inline fragments, code literals и raw HTML сохраняются; HTML не
  исполняется, ссылки/ресурсы не загружаются.
- EOL для новых/пересобранных строк — первый EOL выбранного контейнера, иначе
  первый EOL документа, иначе LF. Существующий final newline сохраняется, если
  контейнер затрагивает EOF; удаление последнего контейнера может дать пустой файл.
  Mixed EOL внутри patch range допускает нормализацию, вне него — нет.
- Ожидаемый tightness задаётся **до** сериализации. Существующий loose list
  остаётся loose, кроме результата с единственным LI и единственным paragraph:
  такой результат становится tight (loose нельзя выразить одними trailing blanks).
  Tight list остаётся tight,
  кроме появления LI с двумя или более непосредственными block children либо
  переноса такого LI в tight list: целевой list становится loose. Новый list
  tight, если каждый LI имеет один непосредственный block, иначе loose.
  Wrap/unwrap пересчитывает только lists, у чьих LI изменилось число blocks,
  по тому же правилу с указанным исключением. Это консервативная политика v2.
  Для подсчёта normalizing view учитывает implicit paragraph tight LI как block.
  Ожидаемое semantic tree строится из входной модели/команды, не из output parse;
  при сравнении tight/loose нормализуются только отсутствующие P wrappers MD4C,
  но не само значение tightness и не block boundaries.
- После patch полный parse сравнивается с ожидаемым transformed tree, включая
  start, task-state, tightness и структуру соседей. Одного успешного parse мало.
  Слияние соседних списков/цитат, reference rebinding или поглощение блока —
  structural mismatch, команда отклоняется без скрытого расширения правки.
- Если удаление последнего LI оставляет внешний LI/QUOTE невыразимым либо
  потребовало бы каскадного удаления родителей, команда отклоняется с диагностикой.
  Контракт удаления списка не разрешает удалять его внешние контейнеры молча.
- Для v2 mutations с lazy continuations, structural tabs, indented code,
  незакрытыми fences или definitions внутри изменяемого контейнера
  отклоняются как unsupported, кроме форм definitions, которые утвердит 025.
  Внешние definitions, не используемые изменяемым поддеревом, не мешают операции
  и сохраняются побайтно. Bound reference links в изменяемом поддереве получают
  обязательную success-матрицу после 025. За пределами patch source допускает
  перечисленные конструкции без их редактирования.

| Сценарий | Ожидаемый результат |
|---|---|
| Вставка в `3. a` / `9. b` | Start 3, номера результата 3/4/5; содержимое старых LI сохранено |

| Удаление единственного LI | Список и его поддерево удалены; соседние bytes сохранены |

| Task none → unchecked → checked → none | Содержимое LI сохранено, меняется только ожидаемый task-state |
| Первый LI indent / top-level LI outdent | Ошибка без изменения документа |

| Loose LI с paragraph + fenced code, quote/list nesting | Содержание блоков и code literals сохранено |
| Wrap contiguous siblings / unwrap nested quote | Один дополнительный / удалённый уровень, без слияния соседей |
| Внешняя неиспользуемая definition вне patch | Success; definition побайтно сохранена |
| Закрытый fence / inline HTML внутри обязательного LI fixture | Success; literal/raw fragment сохранён |

| Пустой/whitespace-only/definition-only fragment | Invalid fragment; нет нового документа |
